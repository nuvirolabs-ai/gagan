# Gagan Field Ops V1 — Cloudflare R2 Staging Evidence Runbook

This runbook is for the remaining hosted collection-evidence blocker. It uses
the existing provider-neutral S3 adapter and introduces no Cloudflare-specific
business logic.

## Exact application configuration contract

Set only these generic object-storage variables on the `gagan-staging-api`
Render service:

```text
STORAGE_PROVIDER=s3
OBJECT_STORAGE_BUCKET=gagan-staging-evidence
OBJECT_STORAGE_REGION=auto
OBJECT_STORAGE_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
OBJECT_STORAGE_ACCESS_KEY=<R2_ACCESS_KEY_ID>
OBJECT_STORAGE_SECRET_KEY=<R2_SECRET_ACCESS_KEY>
```

The current source does not define a storage-prefix environment variable.
Object keys are generated by the application as:

```text
<purpose>/<UTC year>/<UTC month>/<random UUID>
```

`OBJECT_STORAGE_ROOT` is used only by the local adapter. It is ignored when
`STORAGE_PROVIDER=s3`; it may remain in the Render environment for compatibility
but must not be treated as durable storage.

There is no environment variable for signed URL TTL. The collection service
requests a 300-second signed read URL. The storage adapters accept signed-read
expiries from 1 to 900 seconds.

Never place the real access key or secret in Git, a ticket, a screenshot or a
mobile build. Use Render’s secret environment-variable storage.

## Founder setup

1. Sign in to the Cloudflare account that owns the Gagan staging resources.
2. Open **R2 Object Storage** in the Cloudflare dashboard.
3. Create a bucket named `gagan-staging-evidence`.
4. Use the Standard storage class unless the owner has a documented reason to
   choose otherwise.
5. Keep the bucket private. Do not enable public development URLs, custom
   domains or anonymous object access.
6. Open **Manage R2 API Tokens**.
7. Create a token with **Object Read & Write** permission, scoped to the single
   bucket `gagan-staging-evidence`. Do not grant account-wide administration or
   unrelated bucket access.
8. Copy the Access Key ID and Secret Access Key immediately; Cloudflare does
   not show the secret again.
9. Obtain the account ID and set the endpoint exactly to:
   `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.
10. Map the values to the six Render variables above. Do not create R2-named
    variables unless the application source is changed in a separately
    approved task; the current source reads the generic names shown here.

Cloudflare’s current S3 documentation confirms that R2 uses the S3-compatible
endpoint `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, the `auto` region, and
bucket-scoped Object Read & Write credentials. See:

- https://developers.cloudflare.com/r2/get-started/s3/
- https://developers.cloudflare.com/r2/api/tokens/
- https://developers.cloudflare.com/r2/api/s3/presigned-urls/

## Render change boundary

On the existing `gagan-staging-api` service, change only:

```text
STORAGE_PROVIDER: local → s3
OBJECT_STORAGE_BUCKET: add gagan-staging-evidence
OBJECT_STORAGE_REGION: add auto
OBJECT_STORAGE_ENDPOINT: add the account endpoint
OBJECT_STORAGE_ACCESS_KEY: add the R2 access key ID as a secret
OBJECT_STORAGE_SECRET_KEY: add the R2 secret as a secret
```

Leave the accepted backend source, database, JWT, mock-provider, SAP mock,
location, scheduler and CORS configuration unchanged. Redeploy the exact
accepted backend source after saving the environment variables and record the
Render deployment ID and source SHA.

## Smoke test after deployment

Use only the existing clearly marked staging/UAT collection record.

1. On the current Salesperson APK, submit one small cash collection with a
   reference and one small JPEG/PNG receipt.
2. In Admin, verify the collection is visible and the evidence can be opened
   through the authenticated/signed URL.
3. Confirm the collection once. Verify the collection status and ledger/payment
   state change exactly once.
4. Retry the same confirmation and verify the canonical idempotent/rejected
   behavior.
5. Verify the object is not anonymously retrievable.
6. Verify a user without authorization cannot retrieve it through the normal
   application route.
7. Restart/redeploy the API without changing the bucket.
8. Reopen the same collection and verify the evidence remains retrievable.
9. Verify PostgreSQL contains object metadata/key/checksum/size/type and not
   the receipt bytes.
10. Record the deployment ID, source SHA, collection ID, object key (not the
    signed URL), evidence checksum, and screenshots without recording secrets.

## Production reservation

Do not create or configure production in this task. The later production
equivalent should be a separate private bucket named:

```text
gagan-production-evidence
```

It must use separately scoped production credentials and a separately approved
deployment change. Never reuse the staging bucket or staging credentials.
